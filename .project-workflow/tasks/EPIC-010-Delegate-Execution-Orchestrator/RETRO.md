# Epic Retro

- Epic: EPIC-010
- Title: Delegate Execution Orchestrator
- Last updated: 2026-08-19

## Lessons

- Delegate is useful only as a governed execution layer over approved Task or Epic plans. Its durable value is deterministic graph resolution, explicit authority, bounded capacity, write-scope isolation, coordinator verification, resumable machine-local state, and preservation of existing QA/closeout gates—not merely asking a Codex task to create more tasks.
- Native current-Codex proof found integration facts that deterministic tests alone could not establish: requested worktrees begin detached at the exact base, valid workers may return an inspected uncommitted diff, multiple isolated worktrees share the same detached checkout identity, and monitoring capacity is observable as a lower bound rather than a declared platform maximum.
- Capability claims need a tri-state model with dated runtime provenance. Unknown and unsupported are materially different, but neither authorizes persistent or parallel work; Epic children must remain persistent-task-or-coordinator work and cannot silently fall through to session subagents.
- The coordinator must remain the single writer of shared workflow and lifecycle state. Worker completion claims are inputs, not verification, and the non-bypassable all-rows-Done gate before `Testing` protects Delegate integrity even when `--force` is supplied.
- Host assets need semantic release checks, not keyword presence. The previous Delegate prompt was Task-only, fixed at four workers, blanket fail-fast, and copied Copilot placeholders into Claude/Cursor surfaces; exact managed parity and host-native syntax now prevent that drift.
- Proof layers must stay separate. The retained native Task/Epic journeys prove their exact ancestor implementations; the final integrated HEAD is separately proven by the complete deterministic suite and exact-wheel package journeys. No final-wheel native replay, other-host runtime support, release, deployment, adoption, or effectiveness is claimed.
