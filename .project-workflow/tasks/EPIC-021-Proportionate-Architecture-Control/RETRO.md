# Epic Retro

- Epic: EPIC-021
- Title: Proportionate Architecture Control
- Last updated: 2026-09-01

## Lessons

- Architecture gates need adversarial probes for duplicate impact sections, force-path bypasses,
  stale authority, unbound conformance prose, and generated-file drift. Happy-path lifecycle tests
  alone did not establish fail-closed integrity.
- Architecture authority, implementation candidate, and verification receipt identities are
  separate bindings. Keeping all three explicit prevents a current document from certifying stale
  source or a receipt from silently applying to a different candidate.
- Generated semantic parity is not real-host capability. One canonical source and deterministic
  host adapters can be complete while an authenticated Claude canary remains genuinely unavailable.
- Material verification should be initialized before certifying checks. When workflow-evidence-only
  changes leave the exact code candidate unchanged, retained outputs may be regraded with zero new
  target calls under the campaign contract.
- Durable controls now live in the repository architecture spine, lifecycle validators, canonical
  Architect prompt and generator, repository tests, CI checks, and Project Workflow guidance rather
  than in task-specific prose alone.

## Follow-up Tasks

- Run a separate real authenticated Claude discovery and invocation canary when a supported Claude
  runtime is available. Until then, do not claim Claude or cross-host runtime support.
- Consider consumer-repository adoption only through each consumer's own authority and an explicit
  future decision; EPIC-021 does not authorize or prove adoption.

## Deferrals

- None. AC11 explicitly permits the evidenced unavailable-Claude branch, and consumer adoption was
  excluded from this Epic rather than deferred from an acceptance criterion.

## Missed In-Scope Work

- None. The local exact candidate implements, validates and QA-reviews the approved capability while
  preserving the no-push, no-merge, no-release, no-deployment and no-consumer-mutation boundaries.
