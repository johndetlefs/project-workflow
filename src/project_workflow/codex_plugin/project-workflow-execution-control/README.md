# Project Workflow Execution Control

This package-owned Codex plugin contains the subordinate hook handler used by the supervised
`project execute` path. Installing or discovering this plugin does not itself activate material
execution authority or advertise support.

Project Workflow injects the synchronous hook configuration only for a sealed, trusted local
Codex App Server turn after exact executable/configuration capability negotiation. The runtime uses
an ephemeral network-disabled workspace permission profile and thread-scoped hook-trust override;
the handler receives only the sealed control and private atomic state paths. Successful hook
discovery alone is insufficient: Project Workflow also requires observed SessionStart activation,
native App Server events, the exact required workspace changes, stable source identity, and a
core-owned terminal receipt.

The core execution control and `COORDINATION.json` remain authoritative. There is deliberately no
static `hooks.json`, public `project-enforce` command, fixed budget, QA lifecycle, candidate
authority, or release executor in this plugin. Package presence is not installation, activation,
runtime support, release, or adoption proof.
